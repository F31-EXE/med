# Админ-панель Media Expo Group

Закрытая часть сайта med-expo.org для сотрудников (раздел 6 ТЗ).

- `server/` — API: Node, Express 5, TypeScript, Prisma 7, PostgreSQL
- `client/` — интерфейс: Vite, React 19, Ant Design 6, React Router, TanStack Query

## Запуск для разработки

Нужны Node 22+ и PostgreSQL 16.

```bash
npm install
cp server/.env.example server/.env
```

В `server/.env` укажите `DATABASE_URL` (база создастся сама) и `SEED_ADMIN_PASSWORD`. `SHADOW_DATABASE_URL` оставьте пустым: он нужен, только если сервер БД не позволяет Prisma создавать временные базы. Затем:

```bash
npm run db:migrate -w server
npm run db:seed -w server
npm run dev
```

Админка: http://127.0.0.1:5173, API: http://127.0.0.1:4000/api. Vite проксирует `/api` на сервер.

Если SMTP не настроен, письма (например, ссылка для сброса пароля) выводятся в консоль сервера.

## Авторизация

- Вход по e-mail и паролю, сессия в БД, токен в cookie `httpOnly`, `SameSite=Strict`, срок 7 дней с продлением при активности.
- Пароли — bcrypt; токены сессий и сброса пароля хранятся только в виде SHA-256.
- 5 неверных паролей подряд блокируют учётную запись на 15 минут; дополнительно ограничение 20 запросов за 15 минут с одного IP на вход и восстановление.
- Восстановление пароля по ссылке из письма (1 час, одноразовая); после смены пароля все сеансы пользователя завершаются.
- Изменяющие запросы к API принимаются только с заголовком `X-Requested-With: XMLHttpRequest` (защита от CSRF вместе с `SameSite`).
- Роли: `ADMIN`, `EDITOR`, `REGISTRATION_MANAGER`. На сервере — `requireRole(...)`, в интерфейсе — список разделов по роли в `client/src/auth/roles.ts`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/login` | Вход |
| POST | `/api/auth/logout` | Выход |
| GET | `/api/auth/me` | Текущий пользователь |
| POST | `/api/auth/forgot-password` | Письмо со ссылкой для сброса |
| POST | `/api/auth/reset-password` | Новый пароль по токену (сброс или приглашение) |
| POST | `/api/auth/change-password` | Смена своего пароля, остальные сеансы завершаются |
| GET | `/api/users?q=&role=&status=` | Список сотрудников (только администратор) |
| POST | `/api/users` | Добавить сотрудника и отправить приглашение (ссылка на 3 дня) |
| PATCH | `/api/users/:id` | Имя, роль, включение и отключение |
| POST | `/api/users/:id/send-link` | Повторно отправить приглашение или ссылку для сброса пароля |
| GET | `/api/dictionaries/:type?active=true` | Справочник: `directions`, `cities`, `specialties` (все роли) |
| POST, PATCH, DELETE | `/api/dictionaries/:type[/:id]` | Добавить, переименовать или отключить, удалить (только администратор) |
| GET | `/api/events?tab=upcoming\|archive\|trash&q=&status=&format=&directionId=&cityId=&year=&page=` | Список мероприятий, по 20 на страницу |
| GET, POST, PUT | `/api/events[/:id]` | Карточка, создание, сохранение (вместе с направлениями и тарифами) |
| POST | `/api/events/:id/status` | Опубликовать или вернуть в черновик |
| POST | `/api/events/:id/archive` | Перенести в архив вручную или вернуть |
| POST | `/api/events/:id/copy` | Копия черновиком (для ежегодных мероприятий) |
| DELETE | `/api/events/:id` | В корзину |
| POST | `/api/events/:id/restore` | Восстановить из корзины |

## Справочники

Направления, города и специальности ведёт администратор в разделе «Настройки». Названия уникальны без учёта регистра. Значение, которое уже используется в мероприятиях, удалить нельзя — его отключают: из новых форм оно пропадает, а в старых мероприятиях остаётся с пометкой «отключено».

## Мероприятия

Доступны администратору и редактору. Мероприятие создаётся черновиком и публикуется отдельной кнопкой. Адрес страницы формируется из названия и года, если его не задать вручную. После даты окончания (по времени `TIMEZONE`, по умолчанию Екатеринбург) мероприятие само попадает в архив; перенести в архив можно и раньше. Удалённое мероприятие лежит в корзине 30 дней, сервер раз в 6 часов окончательно удаляет просроченные.

Программа, спикеры, документы, партнёры и фото подключаются к мероприятию в следующих модулях.

## Пользователи

Сотрудников добавляет администратор: указывает e-mail, имя и роль, сотрудник получает письмо со ссылкой и сам задаёт пароль. Удаления нет, вместо него учётную запись отключают: доступ пропадает сразу, история сохраняется. Нельзя менять собственную роль, отключать себя и оставлять систему без активного администратора.
