# Сайт и админ-панель Media Expo Group

Сайт med-expo.org и закрытая часть для сотрудников.

- `server/` — API, публичный сайт (серверный рендеринг React, `server/src/site`) и раздача админки: Node, Express 5, TypeScript, Prisma 7, PostgreSQL
- `client/` — интерфейс админки по адресу `/admin`: Vite, React 19, Ant Design 6, React Router, TanStack Query

Оформление сайта и админки — общий стиль «1 + 4» (строгая медицинская подача + мягкие пастельные элементы): токены цветов в `server/public/site.css` (`:root`) и `client/src/theme.ts`, шрифты Inter и Nunito лежат в `server/public/fonts` и отдаются с сервера.

## Запуск для разработки

Нужны Node 22+ и PostgreSQL 16.

```bash
npm install
cp server/.env.example server/.env
```

В `server/.env` укажите `DATABASE_URL` (база создастся сама) и `SEED_ADMIN_PASSWORD`. `SHADOW_DATABASE_URL` оставьте пустым: он нужен, только если сервер БД не позволяет Prisma создавать временные базы. Затем:

```bash
npm run db:migrate -w server
npm run db:seed -w server
npm run db:demo -w server   # необязательно: демо-мероприятия, программа, новости, партнёры, страницы
# или вместо демо — данные старого сайта med-expo.org:
npm run db:import-legacy -w server -- --reset
npm run dev
```

Сайт: http://127.0.0.1:4000, админка: http://127.0.0.1:5173/admin/, API: http://127.0.0.1:4000/api. Vite проксирует `/api`, `/uploads`, `/files` и `/assets` на сервер.

`db:demo` удаляет весь контент (пользователи остаются) и создаёт демо-данные с обложками и логотипами-заглушками. Цифры, имена и реквизиты в нём вымышленные. В production скрипт не запускается.

`db:import-legacy` переносит данные старого сайта med-expo.org из `server/prisma/legacy` (`data.json` и файлы в `files/`): справочники, 46 мероприятий (архив, у семи из них точной даты нет — на сайте показан только год; «Чаклинские чтения — 2026» с итогами и фото, Курган-2026 с оргкомитетом и партнёрами), 5 новостей, партнёров, документы «Сведений», тексты страниц, контакты и реквизиты в настройках, 111 редиректов со старых адресов. Как и `db:demo`, он удаляет контент (пользователи и обращения остаются), поэтому без `--reset` не запускается, если в базе уже есть мероприятия. Уведомления в настройках выключены — включите их в админке. Пропущенные записи (без даты, планы на год) скрипт выводит в конце.

## Production

```bash
npm run build                # server/dist и client/dist
npm run db:deploy -w server
npm run start -w server      # сайт, /admin и /api на одном порту
```

Сервер сам раздаёт собранную админку из `client/dist` по адресу `/admin`. В `.env` укажите `NODE_ENV=production`, `SITE_URL=https://med-expo.org`, `APP_URL=https://med-expo.org/admin` и при необходимости `METRIKA_ID`.

Если SMTP не настроен, письма (например, ссылка для сброса пароля) выводятся в консоль сервера.

## Авторизация

- Вход по e-mail и паролю, сессия в БД, токен в cookie `httpOnly`, `SameSite=Strict`, срок 7 дней с продлением при активности.
- Пароли — bcrypt; токены сессий и сброса пароля хранятся только в виде SHA-256.
- 5 неверных паролей подряд блокируют учётную запись на 15 минут; дополнительно ограничение 20 запросов за 15 минут с одного IP на вход и восстановление.
- Восстановление пароля по ссылке из письма (1 час, одноразовая); после смены пароля все сеансы пользователя завершаются.
- Изменяющие запросы к API принимаются только с заголовком `X-Requested-With: XMLHttpRequest` (защита от CSRF вместе с `SameSite`).
- Роли: `ADMIN`, `EDITOR`, `REGISTRATION_MANAGER`. На сервере — `requireRole(...)`, в интерфейсе — список разделов по роли в `client/src/auth/roles.ts`.

## Справочники

Направления, города и специальности ведёт администратор в разделе «Настройки». Названия уникальны без учёта регистра. Значение, которое уже используется в мероприятиях, удалить нельзя — его отключают: из новых форм оно пропадает, а в старых мероприятиях остаётся с пометкой «отключено».

## Мероприятия

Доступны администратору и редактору. Мероприятие создаётся черновиком и публикуется отдельной кнопкой. Адрес страницы формируется из названия и года, если его не задать вручную. После даты окончания (по времени `TIMEZONE`, по умолчанию Екатеринбург) мероприятие само попадает в архив; перенести в архив можно и раньше. Если точная дата неизвестна (старые архивные мероприятия), отметьте «Точная дата неизвестна»: на сайте вместо дат выводится только год, мероприятие остаётся в фильтре по году, но не попадает в фильтр по месяцу и не получает разметку Schema.org `Event`. Удалённое мероприятие лежит в корзине 30 дней, сервер раз в 6 часов окончательно удаляет просроченные.

При копировании переносятся направления, тарифы, залы и список спикеров; дни программы не копируются, потому что привязаны к датам.

## Спикеры и программа

Спикеры — общий справочник (ФИО, степень, должность, город, биография, фото). Спикера, который указан в мероприятии или сессии, удалить нельзя.

У мероприятия три вкладки: «Основное», «Программа», «Спикеры».

- **Программа:** залы (порядок перетаскиванием), дни в пределах дат мероприятия, сессии и перерывы со временем, залом, отметкой НМО, модераторами и докладчиками. Порядок сессий внутри дня меняется перетаскиванием за значок слева (мышью, пальцем или с клавиатуры: Пробел, стрелки, Пробел) или кнопкой «Упорядочить по времени». Сессия без зала показывается во всех залах.
- **Спикеры:** блок «Спикеры» страницы мероприятия — порядок и роль (председатель, сопредседатель, научный комитет, спикер). Есть подсказка, кого из программы ещё нет в списке.

## Регистрации

Доступны администратору и менеджеру регистрации.

- Список заявок по мероприятию или по всем сразу; вкладки по статусам со счётчиками; фильтры по формату участия, специальности, дате заявки (по `TIMEZONE`) и источнику; поиск по ФИО, e-mail, месту работы и последним цифрам телефона. Фильтры хранятся в адресе страницы.
- Порядок списка: сначала новые заявки, затем подтверждённые и отклонённые, внутри статуса — от свежих к старым.
- Статусы «Новая», «Подтверждена», «Отклонена»: в таблице, в карточке заявки и массово для выбранных. Отклонённые заявки не занимают места; вернуть отклонённую заявку при заполненном лимите нельзя.
- Выгрузка в Excel (.xlsx) с учётом текущих фильтров: закреплённая шапка, автофильтр, дата и время по `TIMEZONE`.
- Настройки регистрации мероприятия: открыта или закрыта, дата закрытия, лимит мест, счётчик на сайте, доступные форматы участия, необязательные поля формы (отчество, место работы, должность, СНИЛС, согласие на рассылку), текст письма-подтверждения. Если лимит меньше уже принятых заявок, показывается предупреждение.
- Ручное добавление заявки (например, по телефону): проверки те же, что для сайта, но закрытая регистрация и лимит не мешают. Дубли по e-mail в рамках мероприятия запрещены.
- Удалить заявку может только администратор — для запросов на удаление персональных данных.

Логика приёма заявки вынесена в `server/src/lib/registrations.ts` (`createRegistration`): проверка полей по настройкам мероприятия, нормализация телефона, проверка СНИЛС по контрольной сумме, дубли, лимит мест под блокировкой строки мероприятия (одновременные заявки не превышают лимит), время согласия на ПДн. Публичная форма сайта будет вызывать её с `enforceAvailability: true`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/registrations?eventId=&status=&format=&specialtyId=&source=&from=&to=&q=&page=` | Заявки и счётчики по статусам |
| GET | `/api/registrations/export?...` | Те же фильтры, файл .xlsx |
| GET | `/api/registrations/events[/:eventId]` | Мероприятия со счётчиками, занятыми местами и настройками |
| PUT | `/api/registrations/events/:eventId/settings` | Настройки регистрации |
| POST | `/api/registrations` | Ручное добавление |
| PATCH | `/api/registrations/:id` | Статус, комментарий менеджера |
| POST | `/api/registrations/bulk-status` | Статус для нескольких заявок |
| DELETE | `/api/registrations/:id` | Удаление (только администратор) |

## Новости

Текст новости хранится как HTML. Сервер очищает его через `sanitize-html` (`server/src/lib/richText.ts`): остаются только разрешённые теги и ссылки http(s), mailto, tel и внутренние `/…`, скрипты и обработчики событий вырезаются. Старый текст без разметки при загрузке превращается в абзацы.

Доступны администратору и редактору.

- Заголовок, анонс, текст в визуальном редакторе (TipTap: обычный абзац, заголовки H1–H6, жирный, курсив, подчёркнутый, зачёркнутый, ссылки, списки, цитаты, разделитель; текст из Word вставляется с форматированием), обложка, галерея до 60 фото с подписями и порядком перетаскиванием (можно загрузить сразу несколько файлов), привязка к мероприятию, адрес страницы, SEO.
- Публикация: черновик, сразу или по расписанию. Запланированная новость хранится со статусом «опубликована» и датой в будущем; сайт показывает только новости с `status = PUBLISHED` и `publishAt <= now()`, поэтому отдельный планировщик не нужен.
- Вкладки «Опубликованные», «Запланированные», «Черновики», «Корзина» со счётчиками; поиск и фильтр по мероприятию.
- Удалённые новости 30 дней лежат в корзине, затем удаляются вместе с просроченными мероприятиями.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/news?tab=all\|draft\|scheduled\|published\|trash&q=&eventId=&page=` | Список и счётчики |
| GET, POST, PUT | `/api/news[/:id]` | Карточка, создание, сохранение вместе с галереей |
| POST | `/api/news/:id/publish` | Опубликовать сейчас или на `publishAt` |
| POST | `/api/news/:id/unpublish` | Вернуть в черновики |
| DELETE | `/api/news/:id` | В корзину; `POST /api/news/:id/restore` — восстановить |
| GET | `/api/events/options?q=&ids=` | Поиск мероприятий для выпадающих списков |

Пресет загрузки `gallery`: основное фото до 1920 px, миниатюра 480×360.

## Документы

Доступны администратору и редактору: раздел «Документы» и вкладка «Документы» у мероприятия.

- Загрузка PDF, DOC, DOCX, XLS, XLSX до 20 МБ. Тип проверяется не только по расширению, но и по сигнатуре файла: переименованный текст или XLSX под видом DOC не пройдёт.
- Размещение: на странице мероприятия и (или) в подразделе «Сведений об образовательной организации» (`/sveden/<раздел>/`, 14 подразделов по приказу Рособрнадзора № 1493 — ключи в `server/src/lib/documents.ts`, перед запуском сверить с действующей редакцией). Документ без размещения доступен только по ссылке. Порядок внутри мероприятия и внутри подраздела — перетаскиванием.
- Постоянная ссылка `/files/<id>`: при замене файла ссылка не меняется, старый файл удаляется с диска. PDF открывается в браузере, остальные скачиваются; имя файла при скачивании — название документа.
- Файлы лежат в `UPLOADS_DIR/documents` и наружу отдаются только через `/files/<id>`; статикой раздаётся лишь `UPLOADS_DIR/images`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/documents?q=&eventId=&section=&unplaced=true&page=` | Список (по мероприятию или подразделу — в заданном порядке) |
| POST | `/api/documents` | Загрузка: `multipart/form-data`, поля `file`, `title`, `description`, `eventId`, `svedenSection` |
| PUT | `/api/documents/:id` | Название, описание, размещение |
| POST | `/api/documents/:id/file` | Замена файла без смены ссылки |
| PUT | `/api/documents/order/event\|section` | Порядок: `{ key, ids }` |
| DELETE | `/api/documents/:id` | Удаление вместе с файлом |
| GET | `/api/documents/sections` | Подразделы «Сведений» с числом документов |
| GET | `/files/:publicId` | Публичная ссылка на файл |

## Партнёры и клиенты

Доступны администратору и редактору: раздел «Партнёры и клиенты» и вкладка «Партнёры» у мероприятия.

- Справочник: название, сайт (адрес без `https://` дополняется), описание, логотип, отметка «показывать в ленте на главной». Порядок ленты на главной — перетаскиванием на вкладке «Лента на главной».
- Логотип: SVG, PNG, JPG или WebP. Пресет загрузки `logo` не обрезает изображение (до 800×400, миниатюра до 320×160) и сохраняет прозрачность; SVG растеризуется в WebP, поэтому скрипты внутри SVG до сайта не доходят.
- У мероприятия партнёры делятся на уровни: генеральный, официальные, информационные; порядок внутри уровня — перетаскиванием. Пустой уровень на сайте скрывается. При копировании мероприятия партнёры копируются.
- Партнёра, указанного в мероприятиях (включая мероприятия в корзине), удалить нельзя.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/partners?q=&page=` · `?home=true` | Справочник · лента на главной в заданном порядке |
| GET, POST, PUT, DELETE | `/api/partners[/:id]` | Партнёр |
| PUT | `/api/partners/home-order` | Порядок ленты на главной: `{ ids }` |
| GET, PUT | `/api/events/:id/partners` | Партнёры мероприятия: `[{ partnerId, level }]` в нужном порядке |

## Страницы и SEO

Доступны администратору и редактору. Набор страниц задан в коде (`server/src/lib/pages.ts`): основные (главная, о компании, мероприятия, новости, контакты), служебные (политика, согласие на ПДн, «Спасибо», поиск, 404) и «Сведения об образовательной организации» с 14 подразделами. Запись в базе появляется при первом сохранении, до этого отдаются значения по умолчанию.

- У каждой страницы: заголовок, текст (абзацы через пустую строку), title и description с предпросмотром сниппета и подсказкой по длине.
- Адрес меняется только у страниц, где это безопасно (о компании, контакты, служебные); адреса главной, каталогов и подразделов «Сведений» фиксированы. Адрес не может совпадать с другой страницей и с разделами `/events`, `/news`, `/sveden`, `/files`, `/uploads`, `/api`, `/admin`.
- Главная: заголовок, подзаголовок и текст кнопки первого экрана. «О компании»: команда (фото, имя, должность) и отзывы (текст, автор, должность, фото) с порядком перетаскиванием.
- SEO мероприятий и новостей — в их карточках.

## Настройки сайта

Только администратор, раздел «Настройки» (там же справочники).

- Контакты: телефон в шапке, до шести телефонов и e-mail с подписями, адрес, режим работы, координаты офиса для карты, реквизиты, ссылки на соцсети.
- Цифры компании для главной и «О компании» — до шести пар «цифра — подпись».
- Уведомления о новых заявках: включение и список адресов (если включено — нужен хотя бы один). Значения читает `getSiteSettings()` из `server/src/routes/settings.ts`; отправку писем подключит приём заявок с сайта.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/pages` | Все страницы с адресами и признаками заполненности |
| GET, PUT | `/api/pages/:key` | Страница: заголовок, адрес, текст, блоки, SEO |
| GET, PUT | `/api/settings` | Настройки сайта: `contacts`, `numbers`, `notifications` |

## Публичный сайт

Страницы рендерятся на сервере (`server/src/site`, React `renderToStaticMarkup`), JavaScript на страницах минимальный (`server/public/site.js`): формы, вкладки программы, обратный отсчёт, маска телефона.

| Адрес | Страница |
|---|---|
| `/` | Главная: первый экран из «Страницы → Главная», цифры из настроек, 6 ближайших мероприятий, форматы, этапы работы, 3 новости, отзывы и лента партнёров, форма заявки |
| `/events`, `/events?tab=archive` | Каталог и архив, фильтры по формату, направлению, городу, году и месяцу, по 12 на страницу |
| `/events/<адрес>` | Страница мероприятия по ТЗ (раздел 4.3): программа по дням и залам, спикеры, площадка с Яндекс.Картой, тарифы, регистрация или итоги, партнёры, документы |
| `/news`, `/news/<адрес>` | Лента и новость с галереей, привязанным мероприятием и кнопками «Поделиться» |
| `/about`, `/contacts` (адреса меняются в админке) | О компании (команда, отзывы), контакты с картой, реквизитами и формой |
| `/sveden`, `/sveden/<подраздел>` | Сведения об образовательной организации: текст подраздела и его документы |
| `/privacy`, `/consent`, `/thanks`, `/search` | Служебные страницы и поиск по мероприятиям, новостям и страницам |
| `/sitemap.xml`, `/robots.txt` | Формируются автоматически |

- Формы регистрации и обратной связи отправляют JSON в `POST /api/public/events/:slug/registrations` и `POST /api/public/contact-requests` (там же проверки, ловушка для ботов и ограничение частоты). Ошибки показываются у полей, после отправки — сообщение об успехе и цель Метрики (`registration`, `contact_request`).
- Версия для слабовидящих включается ссылкой в шапке и работает без JavaScript: настройки (шрифт, цвет, интервал, изображения) хранятся в cookie, панель — над шапкой.
- SEO: `title`/`description` из карточек и «Страниц и SEO» (если пусто — по шаблону), `canonical`, Open Graph, Schema.org (`Organization`, `Event`, `NewsArticle`, `BreadcrumbList`). Страницы с фильтрами и поиск закрыты от индексации.
- Яндекс.Метрика подключается, если задан `METRIKA_ID` и посетитель согласился с cookie-баннером. Скрипт счётчика разрешён в CSP через одноразовый nonce.
- Не сделано: микроразметка `itemprop` для подразделов «Сведений» (нужны структурированные поля вместо свободного текста).
- 301-редиректы со старого сайта хранятся в таблице `Redirect` (`fromPath` → `toPath`, счётчик `hits`) и проверяются до маршрутов сайта для GET/HEAD; таблица кешируется на 60 секунд. Сверяется адрес с параметрами, затем путь и путь без завершающего `/`. Наполняется `db:import-legacy`, правится в базе (раздела в админке пока нет).

## Обращения

- Публичное API без авторизации: `GET /api/public/site` (только опубликованное) и `POST /api/public/contact-requests` (имя, организация, телефон или e-mail, комментарий, согласие на ПДн; скрытое поле-ловушка `website` для ботов; не больше 10 заявок за 15 минут с одного IP; нужен заголовок `X-Requested-With`). Новое обращение уходит письмом на адреса из «Настройки → Уведомления» (без SMTP — в консоль сервера).
- `POST /api/public/events/:slug/registrations` — приём заявки с сайта через `createRegistration` с проверкой лимита и сроков, ловушкой для ботов и ограничением 10 заявок за 15 минут. Участнику уходит письмо-подтверждение (название, даты, место, формат, текст из настроек регистрации, контакты), менеджерам — уведомление, если оно включено.
- `GET /api/public/events/:slug` — данные опубликованного мероприятия (их же использует страница сайта, `loadPublicEvent` в `server/src/routes/publicEvents.ts`).
- Раздел «Обращения» (администратор и менеджер регистрации): список с поиском, статусы «Новое» и «Обработано», комментарий менеджера; удалить может только администратор. API: `GET /api/contact-requests`, `PATCH` и `DELETE /api/contact-requests/:id`.

## Главная админки

Сводка по роли пользователя (`GET /api/dashboard`, обновляется раз в минуту): ближайшие мероприятия с заполненностью мест и предупреждениями (не опубликовано, нет обложки, описания, программы или спикеров, места закончились), новые заявки и заявки за сутки с разбивкой по мероприятиям, запланированные новости и черновики, незаполненные страницы и страницы без SEO. Менеджер регистрации видит мероприятия и заявки, редактор — мероприятия и контент.

## Обложка и итоги мероприятия

- Обложка — в форме мероприятия (пресет `cover`), копируется вместе с мероприятием.
- Вкладка «Итоги»: текст, до 8 цифр, фотогалерея до 100 фото, ссылки на видео и публикации, материалы докладов (документы с `eventSection = RESULTS`, отдельно от основного блока «Документы»). На сайте итоги показываются у прошедших мероприятий вместо регистрации; при копировании не переносятся.
- `GET, PUT /api/events/:id/results`; документы фильтруются и упорядочиваются по `eventSection` (`MAIN` или `RESULTS`).

## Пользователи

Сотрудников добавляет администратор: указывает e-mail, имя и роль, сотрудник получает письмо со ссылкой и сам задаёт пароль. Удаления нет, вместо него учётную запись отключают: доступ пропадает сразу, история сохраняется. Нельзя менять собственную роль, отключать себя и оставлять систему без активного администратора.
